# jairocapua.github.io

Personal portfolio for **Jairo Capua**: a single-page Next.js 16 (App Router)
**static export**, deployed to GitHub Pages. The design is a port of the
[Magic UI portfolio template](https://github.com/magicuidesign/portfolio)
(MIT, © Dillion Verma).

## Tech stack

- **Next.js 16** (App Router, `output: "export"`) + **React 19**
- **TypeScript** + **Tailwind CSS v4** (shadcn/ui neutral theme, light/dark via
  `next-themes`), **Geist** fonts from the `geist` package
- **Magic UI** pieces: `BlurFade`, `Dock`, `FlickeringGrid`, built on **motion**
- **Radix UI** (accordion, avatar, separator, tooltip), **lucide-react** icons
- **react-markdown** for the About summary and project descriptions

## Local development

```bash
npm install
npm run dev      # dev server at http://localhost:3000
npm run build    # static export to ./out
npm run lint     # ESLint 9 flat config (eslint-config-next core-web-vitals)
```

## Project structure

```
src/
  app/                 # layout, the one page, 404, metadata routes, llms.txt
    about/ experience/ hackathons/ skills/ post/ projects/
                       # old per-tab URLs from the previous design; each just
                       # redirects to its section (components/legacy-redirect.tsx)
  components/
    magicui/           # BlurFade, Dock, FlickeringGrid (from the template)
    section/           # work, projects, automations, hackathons, contact
    ui/                # shadcn/ui primitives
    navbar.tsx         # the bottom dock
    project-card.tsx   # project card (lazy-loaded preview video)
    structured-data.tsx  # schema.org JSON-LD
  data/
    resume.ts          # SINGLE SOURCE OF TRUTH for all content
    automation-projects.ts  # automation case studies (SCAR format)
  lib/                 # icon maps, llms.txt builders, cn()
public/
  projects/            # project screenshots, preview loops, full demo videos
  tech/                # tech/tool logos (generated SVGs + a few sourced logos)
  work/ education/ hackathons/   # logos and photos for those sections
  *.jpg *.png          # avatar, app icon
scripts/               # one-off tooling (tech-icon + OG-image generators)
docs/                  # reference docs (project lists) + RAG chatbot plans
```

Files in `public/` use kebab-case names and live in the folder for the section
that shows them.

## Editing content

All profile content (bio, skills, work, education, certifications, projects,
hackathons, and social links) lives in
[`src/data/resume.ts`](src/data/resume.ts); the automation case studies live in
[`src/data/automation-projects.ts`](src/data/automation-projects.ts). Edit those
files; the page, metadata, JSON-LD, and `llms.txt` all read from them.

Social links with `navbar: true` appear in the bottom dock.

## Project videos

Project cards autoplay a short, silent loop (`video` in `resume.ts`) and link
the full recording as a "Demo" badge. Keep the loops small; they were cut from
the full demos with ffmpeg, e.g.:

```bash
ffmpeg -ss 26 -t 16 -i public/projects/jobpilot-demo.mp4 -an -vf "scale=768:-2:flags=lanczos,fps=30" -c:v libx264 -preset slow -crf 28 -pix_fmt yuv420p -movflags +faststart public/projects/jobpilot-preview.mp4
```

## Social card

`src/app/opengraph-image.png` and `twitter-image.png` are generated by
`node scripts/gen-og.mjs` (resvg + Geist). Re-run it after changing the name,
description, or avatar; the script keeps its own copy of those values.

## Tech icons

The logos under `public/tech/*.svg` are generated from the `tech-stack-icons`
package by a one-off script:

```bash
node scripts/extract-tech-icons.mjs
```

Re-run it only when adding or removing skills, and keep its `SLUGS` list in sync
with `SKILL_TO_ICON` in [`src/lib/skill-icons.ts`](src/lib/skill-icons.ts).
Logos drawn only in near-black vanish on the dark theme; list their slugs in
`DARK_ON_DARK` in the same file and they're inverted there.

A handful of full-color brand logos are **not** in the `tech-stack-icons`
package, so the script does not generate them — they were downloaded once into
`public/tech/` and are committed as-is: `gmail.svg`, `googledrive.svg`,
`googlecalendar.svg`, `googlesheets.svg`, `shopify.svg`. The automation
case studies map their tool tags to these logos via `AUTOMATION_TOOL_TO_ICON`
in [`src/lib/skill-icons.ts`](src/lib/skill-icons.ts); to give another tag an
icon, drop an SVG into `public/tech/` and add a mapping entry there.

Some skill logos are sourced the same way (downloaded once, not generated):
`zod.svg`, `tanstack.svg`, `reacthookform.svg`, `betterauth.svg`,
`couchbase.svg`, `agora.svg`, and the certification logo `coursera.svg` from
[Simple Icons](https://simpleicons.org)
(TanStack and Better Auth recolored to black, since the originals are
light-on-transparent), plus `vapi.svg` and `browserbase.svg` from each vendor's
own site icon. To render just one new `tech-stack-icons` logo, pass its slug:
`node scripts/extract-tech-icons.mjs vitest`.

A few logos have no SVG at all and ship as PNGs in the same folder, mapped by
`SKILL_TO_IMAGE` in the same file: `gohighlevel.png`, `base44.png`,
`retellai.png`, `stagehand.png`, `insforge.png`, `scrimba.png` (vendor site
icons), and
`zustand.png` (rendered from the `tech-stack-icons` SVG, which is 141 KB).

## Deployment

Pushing to `main` (or a manual `workflow_dispatch`) triggers
[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml), which runs
`npm ci && npm run build` on Node 22, writes the static site to `out/`, adds
`.nojekyll`, and publishes to GitHub Pages.
